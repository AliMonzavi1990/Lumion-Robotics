# توضیحات ارائه — داشبورد ربات چمن‌زن Lumion Robotics

## ۱. پروژه در یک جمله
یک سیستم Full-Stack برای پایش و کنترل ربات چمن‌زن: ربات (شبیه‌سازی‌شده) داده می‌فرستد، Backend آن را اعتبارسنجی و در PostgreSQL ذخیره می‌کند، ماژول AI پیش‌بینی می‌نویسد، و داشبورد React همه‌چیز را زنده نشان می‌دهد و فرمان‌های اپراتور را به ربات می‌رساند.

## ۲. معماری

```
Robot Simulator ──POST /api/telemetry──▶ ┌────────────────────┐
       ▲                                 │  Node.js + Express │◀── GET /api/robots/1/... ── React Dashboard
       └──GET /api/robot/commands/next── │  (اعتبارسنجی Zod)   │──── POST /commands ◀──────  (Start/Pause/Dock)
                                         └─────────┬──────────┘
Mock AI ──(می‌خواند و می‌نویسد)──────────────────▶ │
                                              PostgreSQL
```

دو گروه API جدا داریم:
- **Robot API** (با کلید `x-api-key`): ربات داده می‌فرستد و فرمان می‌گیرد.
- **Dashboard API**: داشبورد داده می‌خواند و فرمان جدید ثبت می‌کند.

دلیل جداسازی: ربات و اپراتور دو «بازیگر» با سطح دسترسی متفاوت‌اند.

## ۳. جریان داده (برای نمایش زنده)
1. **اپراتور روی Start می‌زند** → داشبورد `POST /commands` می‌فرستد → فرمان با وضعیت `queued` در جدول `commands` ذخیره می‌شود.
2. **ربات هر ۲ ثانیه** فرمان بعدی را می‌پرسد (`commands/next`) → وضعیت فرمان `sent` می‌شود → ربات اجرا می‌کند و `ack` می‌زند (`done`).
3. **ربات تلمتری می‌فرستد** (باتری، وضعیت، مساحت) → Backend با Zod اعتبارسنجی می‌کند → در `telemetry_samples` ذخیره می‌شود.
4. **Backend جلسه را مدیریت می‌کند**: با اولین نمونه `mowing` یک جلسه باز می‌شود، با بازگشت به Dock بسته می‌شود (۹۵٪ مساحت یا بیشتر = Completed، وگرنه Aborted).
5. **ماژول AI** از آخرین نمونه‌های باتری پیش‌بینی می‌سازد و در `predictions` می‌نویسد.
6. **داشبورد** با `usePolling` هر ۲ تا ۳۰ ثانیه داده را دوباره می‌گیرد و نمودارها به‌روز می‌شوند.

## ۴. دیتابیس (۸ جدول)

| جدول | کاربرد |
|---|---|
| `robots` | مشخصات ربات، هش کلید API، آخرین زمان دیده‌شدن |
| `mowing_sessions` | جلسات چمن‌زنی (مساحت، مدت، شارژ، باتری شروع/پایان، موانع) |
| `telemetry_samples` | داده لحظه‌ای ربات |
| `events` | رویدادها و هشدارها |
| `commands` | فرمان‌های اپراتور (`queued → sent → done` یا `expired`) |
| `predictions` | خروجی AI: پیش‌بینی باتری، سلامت قطعات، روز تا سرویس |
| `audit_log` | سابقه عملیات |
| `users` | آماده برای سیستم ورود (هنوز پیاده‌سازی نشده) |

محدودیت‌ها هم در Zod (لایه API) و هم با `CHECK` در خود دیتابیس اعمال شده‌اند (مثلاً باتری بین ۰ تا ۱۰۰).

## ۵. داده پیش‌فرض تولیدی
با `npm run db:setup` هر بار **دقیقاً یک** مجموعه داده ساخته می‌شود (الگوریتم قطعی است):
- ۳۹ جلسه در ۸ هفته (۳ جلسه ناتمام؛ یکی با ۵ مانع تا صفحه AI عبارت «Check needed» نشان بدهد)
- ۲۴ ساعت نمونه باتری + پیش‌بینی AI
- حدود ۵۶ رویداد (مانع، بازگشت به Dock، تعمیر و نگهداری)
- جلسه آخر ۲۲ دقیقه پیش تمام شده و ربات روی Dock در حال شارژ است (~۷۱٪)

داده‌ها با هم سازگارند: جلسه‌ها، نمودار باتری و رویدادها یک خط زمانی واحد را روایت می‌کنند. تست‌های خودکار (`npm test`) این سازگاری را بررسی می‌کنند (مثلاً باتری هیچ‌وقت بیشتر از ۱۰۰ نمی‌شود).

## ۶. نقشه اتصال داشبورد به Backend

| بخش داشبورد | Endpoint |
|---|---|
| کارت باتری + چیپ اتصال | `GET /robots/1/status` |
| کارت مساحت و زمان کارکرد | `GET /robots/1/summary` |
| نمودار باتری (واقعی + AI) | `GET /robots/1/battery` |
| نمودار چمن‌زنی و شارژ | `GET /robots/1/activity` |
| جدول جلسات / رویدادها | `GET /robots/1/sessions`, `/events` |
| صفحه AI insights + کارت نگهداری | `GET /robots/1/insights` |
| دکمه‌های Start / Pause / Dock | `POST /robots/1/commands` |

هیچ داده ساختگی (mock) در Frontend باقی نمانده است.

## ۷. تصمیم‌های طراحی مهم (برای پاسخ به سؤال داور)
- **Polling به‌جای WebSocket:** ساده‌تر و برای نمونه اولیه کافی است.
- **`api.js` تنها جای `fetch`:** کامپوننت‌ها از جزئیات شبکه خبر ندارند.
- **کلید ربات فقط به‌صورت هش ذخیره می‌شود** (SHA-256).
- **انقضای فرمان (۲ دقیقه):** اگر ربات آفلاین باشد، فرمان قدیمی بعداً ناگهان اجرا نمی‌شود.
- **تعریف دقیق زمان‌ها:** `duration_min` = فقط زمان واقعی چمن‌زنی (بدون Pause و Dock)؛ `charging_min` = فقط تا وقتی باتری زیر ۱۰۰٪ است.
- **ماژول AI قابل جایگزینی:** فقط از جدول `predictions` می‌خواند/می‌نویسد؛ مدل واقعی می‌تواند بدون تغییر Backend جایش را بگیرد.

## ۸. سناریوی دمو (۵ دقیقه)
1. داشبورد را باز کنید: ۸ هفته تاریخچه، ربات روی Dock در حال شارژ.
2. **Start** → وضعیت Mowing می‌شود، نمودار باتری پایین می‌رود، جلسه جدید در جدول ظاهر می‌شود.
3. **Pause** و دوباره **Start** → زمان Pause به مدت جلسه اضافه نمی‌شود.
4. **Dock** → رویدادها: «Returning to dock» و «Mower docked, charging».
5. ترمینال شبیه‌ساز را ببندید → چیپ هدر به «Robot offline» تغییر می‌کند.
6. صفحه **AI insights** → زمان باقی‌مانده، هشدار ناهنجاری، سلامت قطعات.
7. (اختیاری) `SIM_BAD=1 npm run sim` → API داده نامعتبر را رد می‌کند و رویداد Warning ثبت می‌شود.

## ۹. محدودیت‌ها و کار آینده (صادقانه بگویید)
- **احراز هویت ندارد:** هر کس به API دسترسی داشته باشد می‌تواند فرمان بفرستد. نسخه بعدی: ورود با JWT و استفاده از جدول `users`.
- ربات شبیه‌سازی شده است و AI یک قاعده ساده (رگرسیون خطی و فرمول فرسایش) است، نه مدل واقعی.
- فقط یک ربات در داشبورد نمایش داده می‌شود.
- جدول‌های تلمتری و پیش‌بینی برای استفاده طولانی به سیاست نگهداری/حذف داده نیاز دارند.
- زمان شارژ در شبیه‌ساز فشرده است (چند دقیقه واقعی به‌جای ساعت).

## ۱۰. اجرا
```
npm run setup      # یک بار
npm run db:up      # PostgreSQL
npm run db:setup   # جدول‌ها + داده پیش‌فرض
npm run api        # ترمینال ۱
npm run sim        # ترمینال ۲
npm run ai         # ترمینال ۳
npm run dev        # ترمینال ۴  →  http://localhost:5173
```
